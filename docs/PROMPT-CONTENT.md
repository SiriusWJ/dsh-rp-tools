# 提示词内容层设计（RP 工具）

> 参考来源：`hermes-roleplay-engine`（`src/character_engine.py:156-185`）的衣物/体位连续性负面清单，
> 它是那份仓库里信息密度最高的约 30 行；本文件把它改写为**通用跑团版**并扩充。
> 用途：作为可注入的系统提示词段落（见 `docs/REFERENCE-COMPARISON.md` 的注入通道设计）。

---

## 为什么这类清单有效

普通写法「请保持连贯」是**祈使句**，模型没有可执行动作。
有效写法是：**把已知的失败模式逐条具名化** + 给一个**自检动作**。

hermes 原文的关键手法（值得保留）：
1. **具体到荒谬**的条目（「趴着却『低头看你』」「双手被占仍『双手环抱』」）—— 模型看到具体反例才会真正避免；
2. 结尾给**具名自检**：「每次生成回复前，先在内心默读上一轮状态栏的『穿搭』和『姿势』字段，以此为基准写本轮内容」；
3. 不是单纯禁令，而是**清单 + 校验规则**。

## 草案：通用跑团版（待审）

> 这一段将作为独立的可注入段落，默认开启，可在设置页关闭。

### 一、身体与空间的物理连续性

- **姿态不能瞬移**：上一轮跪着/躺着/背对着，本轮不能毫无过渡地站着、正面对视。要改姿态就写出动作。
- **视线要对得上**：背对着不能「看着你的眼睛」；隔着桌子不能「凑到你耳边」而不写移动。
- **够不到就别够到**：跪着、被绑着、隔着一扇门，都不能直接完成需要站起/伸手/走近的动作。
- **手被占用就是被占用**：双手抱着人/握着武器/被捆住时，不能再「双手环抱」「同时掏出地图」。
- **穿脱要记账**：刚脱掉的外套不会自己回到身上；要穿回去就写这个动作。水边/雨中场景不能让衣物保持干爽。
- **伤势要留痕**：上一轮受了伤、被击中、跑得脱力，本轮不能健步如飞、无需恢复。
- **负重与体力**：背着人不能同时攀爬；长途奔袭后不该立刻精细操作。
- **在场的人不会凭空消失**：上一轮在场的 NPC 要离场就写他离开；也不能凭空多出没有交代的人。
- **时间要能对上**：说了「一炷香后」就不能下一句瞬间抵达；夜里发生的事不能接在正午之后。
- **已消耗的不会自己回来**：用掉的箭矢、药水、银两、法术位，不写补充就还是空的。

### 二、对话与信息的连续性

- **说过的话算数**：已经说出口的承诺、谎言、透露的情报，不能当作没说过，除非角色**刻意**改口（且要写出改口的动机）。
- **不知道的就是不知道**：角色不能使用他从未获知的信息（不在场时发生的事、别人私下说的话）。
- **口癖与语气要一致**：粗人不会突然出口成章，书生不会突然满口黑话，除非有剧情理由。
- **情绪有惯性**：上一轮还在痛哭，本轮不会突然谈笑风生；要转变就给出过渡链（擦泪 → 抽噎 → 勉强扯出笑 → 笑容变真）。
- **不替玩家做决定**：不能代替玩家角色行动、发言或表态；描述到「等待你的反应」为止。
- **不替玩家下结论**：不能写「你其实很害怕」这类替玩家规定内心状态的句子。

### 三、自检指令（接在清单末尾）

> 每次生成回复前，先在内心核对上一轮的状态栏（地点 / 时间 / 在场者 / 穿着 / 姿态 / 伤势），
> 确认本轮所有动作与它相容；若确有变化，用叙述交代变化过程，不要直接跳到结果。
> 若发现自己已经写出矛盾，宁可当场改口重写，也不要当作没发生。

## 已落地：开局搭世界的工作流（「选小说 → agent 填世界观」）

这一条**不在插件代码里**，在 dm 预设的 persona（`~/.dsh/.agent-presets/dm/agent.cordis.yml`）。
插件只提供落地物（世界书格式 + `rp_lore` 工具 + 角色卡字段），预设负责让 DM 知道该这么做。

DM 开局时会先问玩家世界从哪来，给四个选项（带 action 的按钮卡片）：

1. **照着某部小说/游戏/影视来** —— 玩家给作品名或文件路径
2. **玩家自己有文件** —— 模组、设定集、既有战役记录
3. **原创** —— DM 按玩家口味现场造
4. **玩家已写好世界书** —— 直接读工作区里的 `rp-worldbook.md`

「照着已有作品搭世界」的步骤（写进 persona）：

- 先定死来源与范围（原著？动画？某条支线？）；拿不准的作品**先用 `web_search` 查一轮再动手**，别硬编
- **只取用得到的部分**，不复述整部作品：时代地域 / 核心势力与其矛盾 / 力量体系（能做到什么·做不到什么）/
  当前局势 / 玩家角色的位置
- 写成世界书 + 用 `rp_character` 登记出场人物（含 `first_mes`）
- **把改动摊给玩家看**（新建/改写了哪些条目），玩家说不对就改条目、不在对话里解释
- **二创要标出来**：原作没有的内容标「（二创）」，免得以后把二创当原著用

预设白名单同时加了 `web_search`（已确认它注册在全局，见 `dm-filter.keepGlobalTools`）。

> ⚠️ **改预设要新建会话才生效** —— 组合在会话开始时读取。已在跑的 DM 会话仍旧用旧 persona。

## 已落地的相关改动：角色卡字段（给样本 > 给形容词）

`rp_character` 已从「名字 + 外观」扩成 8 个字段（见 `docs/REFERENCE-COMPARISON.md` §7.2）。
和本文件的关系：**这两个是同一件事的两半** ——

- 角色卡的 `speech` / `behavior` / `first_mes` / `mes_example` 解决「**这个角色**该怎么演」；
- 本文件的物理/对话连续性清单解决「**所有角色**都不能犯的错」。

前者是角色特异性的样本，后者是通用约束。建议的注入顺序：先把通用约束立好，再给角色样本 ——
否则模型会优先模仿样本里的具体写法（包括样本里可能存在的坏习惯）。

**填写建议**（已写进 `rp_character` 的工具描述，让模型自己也照这个填）：

- `speech` 要写**可观察的量化特征**（「句子短、爱用反问、管玩家叫小子」），
  不要写「说话很有个性」—— 形容词对模型没有约束力，具体特征才有。
- `first_mes` 填**该角色初次登场的原文**，它是最有效的文风锚点（注入时取前 300 字）。
- `mes_example` 用「角色名：台词」格式，2~4 轮即可。
